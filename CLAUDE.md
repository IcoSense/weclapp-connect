## Commands

```bash
# Run all tests — works without credentials
npm test

# Lint source files
npm run lint

# Lint and auto-fix
npm run lint:fix
```

Tests use **mocha** (5s timeout) and **chai**, and fall into two groups:

- **Offline** (`test/version.test.js`, `test/v2-method-names.test.js`) — mocks `axios` via
  `Module._load` to assert URL construction, version routing, and the endpoint surface of each
  version, and pins the generated v2 method names against
  `test/fixtures/v2-method-names.json`. Always runs.
- **Smoke** (`test/test.js`) — hits a real tenant, reading `WECLAPP_TENANT` and
  `WECLAPP_APIKEY` from the environment. **Skips itself** when either is unset, so a clean
  checkout is green (14 passing, 2 pending). Never hard-code a token here.

To run a single suite, use mocha's `--grep` flag with one of the suite names —
`version routing`, `endpoint surface`, `binary responses`, `v2 method names`, or `smoke`:

```bash
npx mocha --timeout 5000 --grep "version routing"
```

## Architecture

This is a Node.js library (`@icosense/connect`) that wraps the weclapp REST API. It carries two endpoint sets — v1 (hand-written, 340 methods) and v2 (generated, 1048 methods) — and an instance exposes exactly one of them. The public surface is a factory function in `src/app.js` that returns a bound method object.

### Core flow

1. **`src/app.js`** — Factory function. Accepts `{tenant, domain, apikey, protocol, apiVersion}`, constructs `fetchAPI` (axios-based), spreads the endpoint modules **of the selected version** into one object, then binds `fetchAPI` as the first argument to every endpoint function via `.bind(null, fetchAPI)`. Returns the merged object plus a raw `fetch` escape hatch. `apiVersion` defaults to `'v1'`, accepts `'v1' | 'v2' | 1 | 2` (case-insensitive, optional `v` prefix) and throws on anything else. The two surfaces never mix.

2. **`src/endpoints/*.js`** — Each file exports a plain object of `async` functions. Every function receives `fetch` as its first parameter (injected by `app.js`); callers never pass it. The rest endpoint module follows one consistent pattern:

   ```js
   async getSomething(fetch, {page, pageSize, sort, ...rest}) {
       return fetch(buildUrl('resource', {page, pageSize, sort, ...rest}))
   },
   async getSomethingById(fetch, id) {
       return fetch(`resource/id/${id}`)
   },
   async createSomething(fetch, body) {
       return fetch('resource', {method: 'POST', body})
   },
   async updateSomethingForId(fetch, id, body) {
       return fetch(`resource/id/${id}`, {method: 'PUT', body})
   }
   ```

3. **`src/endpoints/v2/*.js`** — Generated by `scripts/generate-v2.js` from `apidoc/weclapp-openapi-v2.yaml`; `index.js` spreads them all. Same `fetch`-first convention, but one mechanical naming scheme (`query{R}`, `count{R}`, `create{R}`, `get{R}ById`, `update{R}ById`, `delete{R}ById`, `{action}{R}[ById]`) and a trailing optional query object only where the operation declares query parameters. **Do not hand-edit these** — regenerate instead.

4. **`src/utils.js`** — Exports `buildUrl(url, obj)`: appends truthy key/value pairs from `obj` as URL-encoded query parameters. Note that falsy values are dropped, so `page: 0` never reaches the URL.

### Adding a new endpoint

**v1**: create `src/endpoints/<resourceName>.js` following the pattern above, then add a `...require('./endpoints/<resourceName>')` spread in the `endpoints` object in `src/app.js`. Use a relative `require('../utils')` — never the package's own name.

**v2**: do not add files by hand. Refresh `apidoc/weclapp-openapi-v2.yaml`, run `npm run generate:v2`, review the diff, then `npm run update:v2-fixture` to re-record `test/fixtures/v2-method-names.json`. The fixture test fails by name if a regeneration drops or renames a method; new names are reported, not failed.

### API URL pattern

All requests go to:  
`{protocol}://{domain || tenant.weclapp.com}/webapp/api/{apiVersion}/{endpoint}`

Authentication is via the `AuthenticationToken` header. Errors are not wrapped: axios' default `validateStatus` rejects 4xx/5xx itself, so callers see an `AxiosError` with the server answer on `err.response`.

`migration/` holds two generated maps (methods and fields) comparing the v1 and v2 specs — see the README's migration section before porting a consumer.

## Code Style

- **Indentation**: tabs (enforced by ESLint and `.editorconfig`)
- **Line endings**: not enforced by ESLint — do not add a rule for it. `.gitattributes` sets `* text=auto`, so the repo stores LF and every platform checks out natively (CRLF on Windows, LF in CI). A `linebreak-style` rule can only ever pass on one of those; the previous `windows` setting made `npm run lint` fail on every Linux checkout, CI included.
- **ES version**: ES2018 (async/await, object spread)
- **Modules**: CommonJS (`require`/`module.exports`)
